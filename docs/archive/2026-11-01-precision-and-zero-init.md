# Precision and zero init, 2026-11-01

Decided after the first GPU smoke runs (`FACTS.md`, GPU smoke runs). Each entry: what, and why.

| # | Decision | Reason |
|---|---|---|
| 1 | Training precision (PLAN C4): a pure bf16 model with stochastic rounding, not fp32 + TF32 and not autocast | Stochastic rounding makes bf16 work. It is the path Usui was built and measured on (its LFM and Anima runs load a bf16 model; its README lists autocast as untested). Measured at 128 px, one bf16 seed: a slower start (+0.006 over steps 1–50), no difference beyond noise from step 100, 14% faster (FACTS) |
| 2 | Zero-init roles (PLAN A1): Usui trains every matrix, the zero-initialized final linear included, with Usui's fixed step (`lr` and the matrix's shape, not `‖W‖`), under a linear LR warmup. A matrix with no frame and an exactly zero gradient fits none and waits for a real one. The conv (4-D, Usui rejects it), the adaLN tables and the null embedding stay on the fallback; the gate rows move with the shared projection | Usui works with a fixed step size too; for an empty model trust scaling is not wanted but a fixed lr, and the last layer does not go on Adam. Trust scaling suits finetuning, where roles need different steps; a zero matrix has no norm to scale by. A norm floor (the step sized against `max(‖W‖, √128)`) was tried and dropped: the trained final linear sits at 3.5–3.9, so it never outgrew the floor and took a fixed `lr·11.3` step with no coherence; loss 1.853 against 1.539 over steps 201–300. The zero-gradient rule alone gave 1.534, and 0.026 lower over steps 1–50 (FACTS, GPU smoke runs). Built on usuitrack branch `zero-init` (`step_rule`, the zero-gradient rule), to be reviewed for `lab` with `docs/REVIEW_zero-init.md` there; when it merges, `pyproject.toml` points back at `../usuitrack` |
